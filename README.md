# Календарь звонков

Сервис бронирования тайм-слотов для звонков, по типу [Calendly](https://calendly.com/) / [Cal.com](https://cal.com/). Разработан совместно с ИИ-агентами в рамках курса «ИИ для разработчиков 2.0» (Hexlet) — этап 1 проекта.

## Пользовательский сценарий (по референсу Cal.com)

### Роль владельца (создание типа встречи)

1. Владелец открывает приложение и попадает в свой личный кабинет (админ-часть)
2. Создаёт **тип встречи**: задаёт название (например, «Звонок по проекту»), длительность (15/30/60 минут), описание и цвет
3. Настраивает **расписание доступности**: дни недели и часы, в которые возможно бронирование
4. Публикует тип встречи — появляется ссылка на публичную страницу бронирования
5. Делится ссылкой с гостем (в сообщении, письме и т.п.)

### Роль гостя (запись на встречу)

1. Гость открывает ссылку на страницу бронирования владельца
2. Выбирает день и свободный слот в календаре (занятые и вне расписания слоты недоступны)
3. Вводит имя, email и комментарий — подтверждает запись
4. Слот блокируется: становится недоступным для повторного бронирования другими гостями
5. Гость видит подтверждение брони на экране

### Результат для владельца

6. Новая запись появляется в списке броней владельца: дата/время, имя и контакты гостя
7. Владелец может просмотреть и при необходимости отменить бронь — слот снова освобождается

### Обязательные функции и ограничения (из задания)

- Создание типа встречи и настройка доступности — без регистрации гостей
- Гость бронируется только в свободный слот; защита от двойного бронирования
- Просмотр списка записей владельцем
- Внешние календари и email-уведомления — **не входят** в задание
- Требования к генерации клиента: API-контракт описан заранее (TypeSpec), клиент генерируется из спецификации

Референс пользовательского пути: [Cal.com](https://cal.com/)

## Суть задачи

Разработать веб-приложение для бронирования календаря по схеме **Design First** — API-контракт проектируется до написания кода:

1. **API-контракт и архитектура** — собираем требования и описываем контракт с помощью [TypeSpec](https://typespec.io/) до первой строки кода
2. **Разработка с ИИ-агентами** — составляем план, декомпозируем задачи и реализуем через агента (в идеале — ни одной строки кода руками)
3. **Функционал приложения** — реализуем ключевые пользовательские сценарии и покрываем их тестами
4. **Интеграционное и E2E тестирование** — проверяем ключевые пути приложения
5. **CI/CD** — непрерывная интеграция и деплой в PaaS (через MCP)
6. **Деплой** — приложение собирается в Docker-образ и запускается в контейнере

## Стек

## Установка

Требуется [mise](https://mise.jdx.dev) (версии инструментов зафиксированы в `mise.toml`).

```bash
git clone https://github.com/ZhTaha/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise install
npm install
```

## Использование

Запуск приложения:

```bash
mise run start
```

Фоновый dev-сервер (под управлением pitchfork):

```bash
mise daemons start server
mise daemons stop server
```

Проверки (контракт TypeSpec → OpenAPI, ESLint, тесты):

```bash
mise run check
```

Запуск в Docker:

```bash
docker compose up
```
